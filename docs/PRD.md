# Briefy 产品需求文档（PRD）

> 版本：v0.1 | 更新日期：2026-08-27

## 1. 一句话定位

让用户像排报纸一样，用 AI 自动填充内容，制作属于自己的个性化报纸/读物。

## 2. 核心用户流程

```
配置 AI Key → 新建文档(A4) → 添加内容框+写提示词 → 排版调整 → 保存设计
     → 点击"生成" → AI 批量填充所有内容框 → 预览 → 导出 PDF
```

## 3. 功能需求

### 3.1 设置

- 用户配置 AI 服务：API Key、Base URL、模型名（兼容 OpenAI 格式即可）。
- 配置持久化保存在本地。

> 核心理念：**"内容规划"与"内容生成"彻底分离**——用户只负责布局和意图，AI 负责填充和呈现。（源自第三方建议稿，经确认采纳）

### 3.2 编辑器（核心）

- **画布**：所见即所得的 A4 页面，多页管理（添加/删除页），类似 Word 初始视图。
- **添加内容**：用户在纸上框选一块矩形区域，创建"内容框"。
  - 每个内容框可设置：提示词（想要什么内容）、内容形式（纯文字/带图片/表格……）、AI 可使用的工具。
  - 区块样式仅限：位置、大小、顺序、边框、底色、标题级别（不做区块内文字编辑）。
- **排版操作**：
  - 内容框自由拖动、缩放；
  - 删除框、添加新页、调整分页与排版；
  - 不要求提供编辑 AI 填充后的正文细节（不是本软件职责）。

### 3.3 排版预设

- 内置若干开箱即用的预设（如：每日科技报、财经日报、个人周报等），一键套用。
- 第一次打开就能用预设一键生成当天新闻；日常只需更换提示词主题。

### 3.4 布局协议（LayoutSpec）

- 设计文件采用自定义 JSON Schema 描述：页面尺寸、区块坐标/大小/类型、每个区块的提示词与工具权限列表；
- 保存的设计 = LayoutSpec 文档；生成请求也基于它组装。

### 3.5 AI 生成流水线

- 点击"生成"时，将每个内容框的 提示词 + 工具用法 + 全局预设提示词 + 排版规则 组装后发给 AI；
- 多个内容框**并行**生成（并发数可配置）；需要工具的区块先执行工具、把结果注入提示词；
- **流式预览**：生成过程中各内容框逐步显示输出；
- **区块级重试**：某区块结果不满意可单独重新生成，不影响其他区块；
- 全部失败可整体重试。

### 3.6 文件系统

- 设计文件保存/打开（自定义格式 `.briefy`，即 LayoutSpec JSON）；
- 导出成品：**PDF 为首选**；如有必要支持 Word 等利于二次编辑的格式。

### 3.7 UI 风格

- 简洁明了，模仿 Microsoft Word 的布局与交互语言（Ribbon/工具栏 + 中央画布 + 右侧属性面板）；
- 易于上手，但暴露足够的细节供进阶用户调节。

## 4. 非功能需求

- **开源协议**：MIT。
- **本地优先**：所有数据存本地，Key 只存本地不外传（除发给所配 AI 服务商）。
- **跨平台**：优先 Windows，兼顾 macOS/Linux（依技术栈而定）。

## 5. 明确不做

- 富文本正文编辑器（不需要编辑 AI 填充的内容本身）；
- 云端账号体系、协作功能；
- 移动端。

## 7. 技术选型（2026-08-27 与用户确认）

| 层面 | 选型 | 说明 |
| --- | --- | --- |
| 应用形态 | Electron | 桌面软件体验，类 Word；PDF 导出可走打印引擎 |
| 前端框架 | React + TypeScript | 生态最大，拖拽/组件库选择多 |
| AI 编排 | Vercel AI SDK | TS 原生、轻量；原生流式输出、tool calling、OpenAI 兼容 Provider |
| 存储 | 纯 JSON 文件 | `.briefy` 即 LayoutSpec JSON，透明可备份，不用 SQLite |
| 导出 | PDF 首选 | Word 格式导出视需要再加 |

> AI 库选型讨论记录：曾考虑 LangChain.js，因其链式编排/RAG 能力本项目用不上、抽象层厚调试难而放弃；Briefy 的生成任务本质是"每区块一次独立生成"的 map 操作，AI SDK 足够。
