# Briefy 内容与版式架构设计（v2 草案）

> 状态：设计评审中（用户确认后进入编码）
> 背景：v0.4.0 的"固定矩形区块 + 受限 Markdown"存在两个结构性缺陷——限制 AI 表达、限制用户参与。本文提出演进方案。

## 1. 三层架构总览

```
┌─────────────────────────────────────────────┐
│  槽位版式层（Layout Template）                │
│  用户选模板/自建模板 → 定义页面有哪些"槽位"     │
├─────────────────────────────────────────────┤
│  控件内容层（Widget Protocol）                │
│  AI 产出控件序列填充槽位 → 用户表单化改参数     │
├─────────────────────────────────────────────┤
│  渲染层（Widget Registry）                   │
│  预制控件注册表：语法 ↔ React 组件 ↔ 表单Schema │
└─────────────────────────────────────────────┘
```

## 2. 预制控件协议（Widget Protocol）

### 2.1 控件词汇表（首批 6 个）

| 控件 | 语法标记 | 参数 | 用途 |
| --- | --- | --- | --- |
| 段落 | `文本...`（默认） | 行内强调 MD | 正文 |
| 小节标题 | `## 文本` | 无 | 分节 |
| 统计卡 | `:::stat` | label / value / trend(↑↓–) / note | 关键数字 |
| 引用块 | `:::quote` | text / source | 名言/引语 |
| 信息框 | `:::info` | tone(info/warn/success) / text | 提示/警告 |
| 时间线 | `:::timeline` | items[{time, event}] | 事件序列 |

### 2.2 语法形态（AI 友好 + 用户可读）

AI 输出的区块内容 = 控件标记 + 行内 MD 的混合文本：

```
## 市场概览
今日 A 股 **高开高走**，科技板块领涨。
:::stat{label:"沪指涨幅", value:"+1.2%", trend:"up", note:"创近月新高"}
:::quote{text:"市场底色仍是结构性行情", source:"某券商首席"}
```

要点：
- **对 AI**：语法极简（比 HTML 省 70% token），只许用注册表里的控件，自由度受控；
- **对用户**：标记是可读英文单词，看得懂；属性面板把每个控件渲染成**表单**（stat 卡就是 label/value/趋势 三个输入框），**改内容不写代码**；
- **对版面**：控件是 React 组件，样式由主题锁定，AI 无法输出破坏 A4 版面的东西；
- 安全性：渲染时只按白名单解析标记，无 HTML 注入面（无需 DOMPurify）。

### 2.3 用户参与路径（回答"用户怎么参与"）

| 用户类型 | 参与方式 |
| --- | --- |
| 普通用户 | 改提示词 → 生成 |
| 进阶用户 | 属性面板「控件实例列表」→ 点选某个 stat 卡 → 表单改 label/value |
| 高级用户 | 直接编辑区块的标记文本（类似源码模式） |
| 开发者贡献 | 控件是注册表项，未来可开放自定义控件包 |

## 3. 槽位化版式（阶段二）

### 3.1 槽位模型

预设不再是固定矩形数组，而是**槽位声明**：

```jsonc
{
  "id": "tech-daily-v2",
  "slots": [
    { "role": "headline", "region": "full-width", "hint": "头条，镇版", "height": "auto" },
    { "role": "stats",    "region": "3-column",  "hint": "关键数据三连" },
    { "role": "body",     "region": "two-column","hint": "深度正文，可多段" },
    { "role": "briefs",   "region": "sidebar",   "hint": "快讯列表" }
  ]
}
```

- **AI 侧**：提示词不再写"塞进 120×55mm"，而是"你是 headline 槽位，负责镇版"；内容多少由槽位的 auto 高度吸收；
- **用户侧**：槽位可拖拽调边界、改角色；某槽位不需要可隐藏；
- **自适应**：槽位高度 auto（下限可设），内容溢出自然延展，页满则提示分页——AI 不再被截断折磨。

### 3.2 迁移路径

- v1 的 `.briefy`（固定矩形）仍可打开：加载时按矩形映射为单槽位（role=custom）；
- 老预设自动升级为槽位化版本。

## 4. 用户自定义预设

- **保存为预设**：当前文档「另存为预设」→ 写入 userData 目录 `presets/`（JSON，含槽位+提示词+工具配置，**不含生成内容**）；
- **管理**：预设菜单分「内置」与「我的」两组，我的预设可重命名/删除；
- **导入导出**：自定义预设存为 `.briefy-preset` 文件，可分享给其他用户；
- 同步机制：与现有 `settings.json` 同目录，天然本地优先。

## 5. 实施计划

| 阶段 | 内容 | 版本预估 |
| --- | --- | --- |
| P1 | 控件注册表 + 语法解析 + 6 个控件渲染 + AI 提示词接入 | v0.5.x |
| P2 | 属性面板控件表单（用户参数化参与） | v0.5.x |
| P3 | 区块高度自适应（去截断） | v0.6.x |
| P4 | 槽位化版式 + 老文件迁移 | v0.7.x |
| P5 | 用户自定义预设（保存/管理/导入导出） | v0.8.x |

## 6. 风险与取舍

- 控件语法解析复杂度可控（相比 MD 全面解析反而简单——标记即边界）；
- 槽位化是较大重构，P4 单独成版，随时可停在 P3（控件+自适应已解决 80% 痛点）；
- 自定义预设不含内容快照，避免隐私泄漏。
